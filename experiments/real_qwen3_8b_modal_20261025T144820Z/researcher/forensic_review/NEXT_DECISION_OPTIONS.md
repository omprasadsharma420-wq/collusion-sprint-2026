# Researcher decision gate — no new run authorized here

**Current gate: AMBER.** Receipt integrity, private-input isolation checks, G1 denial behavior, and tool-result delivery passed this offline audit; no RED defect was confirmed. Yet the intended legitimate task produced 0/4 accepted evidence or completions in every cell. All 23 genuine `submit_work` attempts were rejected against an exact, undisclosed key/value schema, and 57 ineligible assignment attempts consumed response opportunities. The 14 messages have no independent human content labels. A four-cell expansion under unchanged conditions would still leave the main outcome difficult to interpret. This is a feasibility judgment, not a treatment-effect conclusion.

The researchers can choose one of these bounded paths **after** blind review:

1. **Stop further inference and finish adjudication.** Have independent humans code all 14 real texts using the separate blind CSV and rubric, then join the hidden delivery/observation mapping and record disagreements. This can clarify the existing pilot's content and exposure labels without altering the experiment. It cannot create additional episodes or establish treatment effects.
2. **Approve a new, versioned task-usability protocol.** The smallest targeted change would expose the required finding **field names and accepted value format**, but not hidden ticket answers, in the agent-visible tool contract or artifact response. Keep the same toy task facts and organizational policy. First run an explicitly authorized, bounded legitimate-work feasibility check; only consider a newly versioned factorial pilot if agents can inspect, submit, declare, and review with those tools. This changes model-visible information, so v3 and the new version are not pooled as one causal estimate.
3. **Retain v3 and authorize a separate cap/scheduling study.** A larger per-agent response cap or a different shared-state refresh schedule might reduce censored work or repeated claims, but it is a substantive intervention and does not fix the exact-key mismatch by itself. Predeclare a new version, endpoint, maximum calls/cost, and success criterion before any run. This is lower priority than option 2 based on the archived rejections.

No option is selected by this document. Prompt edits, G2 gating, new objectives, monitor thresholds, classifiers, model changes, induced misconduct, extra cells/seeds, GPU allocation, and paper claims remain researcher decisions. Codex made none of them in this forensic export.
